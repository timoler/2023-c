## 2. 问题目标
第一问要求：3000 支参赛队、125 位评审专家，每件作品由 **5 位不同专家** 评审。需要确定一种「交叉分发」方案，使得：
1. 每位专家评审的作品数量尽量均衡；
2. 任意两位专家「共同评审」的作品数（交叉次数）尽量均衡，从而保证不同专家评分之间的可比性。

最终输出：完整的作品—专家分配方案，以及可量化的评价指标和实施细节。

## 3. 数据与预处理
- 输入文件：本问是纯组合分配问题，**不依赖任何评分数据**。题目附件 `数据/数据1.xlsx`、`数据/数据2.1 .xlsx`、`数据/数据2.2 .xlsx` 为第二问所用，第一问仅使用题面给出的三个规模参数（3000 作品、125 专家、每作品 5 专家）。
- 数据规模：3000 行分配方案，每行 5 位专家；125 位专家；专家对共 7750 对。
- 缺失值/异常值：不适用（无外部数据输入）。
- 与其他问题的依赖：无。本问的分配方案可作为后续问题（评分标准化、防作弊）的基础，但后续问题不反向影响本问。

## 4. 模型与方法
- 假设与符号定义：见 [q1_solution.md](docs/q1_solution.md) 第 2 节。
- 核心公式与参数：交叉次数 `c_{jk}`、理论均值 `μ = N·C(K,2)/C(M,2) ≈ 3.8709`，目标为最小化交叉次数相对 `μ` 的偏离。
- 算法步骤与依据：逐篇贪心分配，代价 = 工作量代价 + 2×交叉代价；另设 100 次随机均衡分配作为基线对照。详见 [q1_solution.md](docs/q1_solution.md) 第 4 节。
- 完整解答：[q1_solution.md](docs/q1_solution.md)

## 5. 环境与运行
- 操作系统：Windows 11；语言：Python 3.x；依赖版本见 `问题一/requirements.txt`。
- 命令执行位置：**仓库根目录**（脚本使用 `问题一/…` 相对路径）。

- 输出路径及会覆盖的文件：运行会覆盖 `问题一/results/` 与 `问题一/figures/` 下对应的 CSV/PNG；`q1_solve.py` 同时负责求解与绘图（未单列 `q1_plot.py`）。

```bash

python 问题一/q1_solve.py
```

说明：`q1_baseline.py` 会读取 `q1_solve.py` 生成的 `问题一/results/q1_cross_counts.csv` 作为贪心对比值，因此**必须先运行 `q1_solve.py`**。绘图脚本会弹出 matplotlib 窗口，关闭窗口后程序继续；无图形界面环境可设置 `MPLBACKEND=Agg` 后再运行。

## 6. 结果与数据字典
| 文件 | 字段 | 含义与单位 |
| --- | --- | --- |
| [results/q1_assignment.csv](results/q1_assignment.csv) | `作品编号`、`专家1`~`专家5` | 每件作品的 5 位评审专家编号（1~125），作品与专家编号均为整数，无前导零 |

| [results/q1_cross_distribution.csv](results/q1_cross_distribution.csv) | `共同评审次数`、`专家对数量`、`比例` | 交叉次数的频数与占比 |
| [results/q1_metrics.csv](results/q1_metrics.csv) | `指标`、`数值`、`方向`、`说明` | 评价指标汇总，「方向」标注越大/越小越好 |
| [results/q1_random_baseline_100runs.csv](results/q1_random_baseline_100runs.csv) | `run`、`seed` 及若干指标 | 100 次随机均衡分配的各项指标 |
| [results/q1_comparison.csv](results/q1_comparison.csv) | `指标`、`随机分配100次均值`、`均衡贪心` | 贪心方案与随机基线的对比 |

核心结果：每位专家工作量恰为 **120 篇**（标准差 0）；专家对交叉次数全部落在 **3~5 次**，其中 **97.26%** 为 3~4 次；交叉次数标准差 **0.4088**，均方误差 MSE **0.1671**（随机基线 100 次均值对应为 1.9039 与 3.625）。该方案回答了题目第一问「确定最优交叉分发方案并讨论有关指标」的要求。
