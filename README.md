# 2023 年研究生数学建模 C 题

大规模创新类竞赛评审方案研究，供队员共享题目、数据、代码与实验结果。

## 开始前必读：协作规范

所有协作者在克隆或拉取仓库后、开始修改前，必须阅读并遵守 [协作规范.md](协作规范.md)。该规范适用于全部四问，不固定人员分工，是文件命名、成果交付和合并检查的统一依据。

- 每问交付必须包含 README、完整解答、可运行代码、依赖说明、结果数据和图表。
- **题号必须一眼可辨**：每问成果放在 `问题一/`～`问题四/`，代码、图片、结果和解答文件同时以 `q1_`～`q4_` 开头；单独传输时也保留题号。固定入口文件与原始附件的例外见协作规范。
- 每问至少提供一张有效图；图片统一使用 `qN_figXX_内容.png` 命名，并提供底层数据或数据引用、生成方式及图题说明。
- 每问 README 必须按规范中的模板填写；完成前逐项检查交付清单。阶段成果需明确标注“进行中”和缺项。
- 通过工作分支提交并发起 PR，由另一人按照规范检查后合并到 `main`。接手前先同步，修改后同步更新受影响的文档、结果和图片。
- 现有旧文件逐步整理；新增和修改的交付成果按规范执行，尚未整理的部分必须明确说明。

使用编程助手时，还须遵守根目录 [AGENTS.md](AGENTS.md) 中的项目指引。以上属于项目协作要求，尚未配置自动阻止不合规提交的 CI 检查。

## 读取与运行

队员接受私有仓库邀请后，可以在 GitHub 页面浏览文件，或通过 Code → Download ZIP 下载；使用 Git 的队员可以克隆仓库。

第一问在仓库根目录安装依赖并运行：

```powershell
python -m pip install -r 问题一/requirements.txt
python 问题一/q1_solve.py
python 问题一/q1_baseline.py
```

运行会覆盖 `问题一/results/` 与 `问题一/figures/` 下对应的 CSV 和 PNG。绘图脚本会弹出窗口，关闭窗口后继续；中文显示需要 Microsoft YaHei 或 SimHei 字体。`q1_baseline.py` 依赖 `q1_solve.py` 先生成贪心结果，运行顺序不可颠倒。详见 [问题一/README.md](问题一/README.md)。

## 协作约定

- 题目与原始数据保留原文件，分析结果按规范放到对应问题的 `results/`、`figures/` 目录。
- 更新代码时说明目的，以及是否重新生成实验结果；重命名文件时同步修改脚本路径和文档链接。
- 个人私有仓库由所有者邀请协作者，协作者具有读写权限；严格只读需要使用组织仓库。建议通过分支和 Pull Request 合并修改。
